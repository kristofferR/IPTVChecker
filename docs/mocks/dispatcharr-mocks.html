2 · Channel-first table

For a Dispatcharr source the table shows one row per channel; the scan still checks every stream. Shared across variants:

  • Status cell becomes a rollup: one bar per stream in failover order (primary wider, set apart), then alive/total. Count turns amber when the primary is dead, red when all are.
  • Media columns show the primary stream, since that is what viewers get. A dead primary shows dashes plus a red Primary dead marker.
  • Fix order: alive by height desc, then frame rate desc (ties keep order), then untested, then geoblocked/DRM/placeholder; dead removed. All-dead channels are skipped and flagged, never emptied. Every write keeps the previous order for Undo. Ranking is configurable, see section 3.
  • Writes go straight to Dispatcharr. No staging dialog; only bulk actions confirm.
  • Filters: status gets Primary dead, Has dead streams and All dead; the stats pills count channels.
  • Report panel is closed in these frames so the full column set shows; it still auto-reveals after a scan by default.

V1Inline: chevron to expand, hover buttons on rows Anbefalt

Per-stream stats line up under the channel's own columns, and actions sit where the eye already is; hover-only buttons are less discoverable.

3 · Fix order preferences

A new Dispatcharr tab in Settings, after Network. Scanning is already long, and these only matter for Dispatcharr sources; the tab bar has room for a sixth 72px tab. Holds the ranking, provider order, dead-stream handling, the live preview and the write-back switch (off by default).

  • Not a setting: untested streams go right after working ones, then geoblocked/DRM/placeholder. Untested is unknown, not bad. A geoblock is measured from this Mac, not from the Dispatcharr server, so it must never rank as dead.
  • Frame rate direction answers "30 fps above 60 fps". Criterion order answers "720p60 or 1080p30".
  • Latency and bitrate compare in coarse bands (latency in 250 ms steps) so scan noise does not reshuffle channels on every run.
  • Preview uses a real multi-stream channel from the loaded source; "was n" marks moved streams.

Notes for implementation

  • Undo keeps the channel's previous stream ID list and writes it back with the same PATCH. Streams removed by Fix are only unlinked, never hard-deleted, so Undo can relink them.
  • Before each write, re-fetch the channel's streams; if they changed in Dispatcharr since load, skip it and show it as a failure (Changed in Dispatcharr, Reload).
  • Fix all counts come from the whole source (36 channels), not just visible rows.
