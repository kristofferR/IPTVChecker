IPTV Player, design notes

A watching-first flavor of IPTV Checker (issue kristofferR/IPTVChecker#231). Soft fork: one repo, two build flavors sharing the Rust crate and frontend core. Status: early notes only; the mock below is the initial direction and much more design work is needed before implementation. Catch-up/EPG groundwork lives in the Checker design doc: https://plans.kristofferr.com/d/5nwq8d7wj9h8

Same codebase rejiggered into a watching-first app: channel zapper list on the left, player as the primary surface, EPG-driven now/next and archive rail below it. All checker machinery (scan, statuses, verification, report, export) is gone from the UI. Everything violet built above (archive URL builder, XMLTV store, seek player, EPG grid) is the core of this app, which is why it should be built player-grade in Checker first.

  • 1Zapper list replaces the table: favorites pinned on top, now-playing programme under each name (EPG), arrow keys and number entry zap. Click = play, no selection concept.
  • 2Player is the primary surface, always on. Same engine as Checker's sidebar player with the seek/archive work from A/B. ⛶ fullscreen; the same Watch / Guide switch as in C flips to the full programme guide.
  • 3Now / Next / Archive rail under the player: click an archive block to replay it, the rail scrolls back through the channel's depth.
  • 4Toolbar shrinks to player needs: playlist switcher, group, search, guide, settings. Scan, Save, Export, Report, status filters, verification: not present in this flavor.
  • Soft fork, not a hard fork: one repo, two build flavors. Shared Rust crate (parser, Xtream/Stalker, proxy, catch-up URLs, EPG store) and shared frontend libs/player components; two thin app shells with separate tauri.conf, product name, and icon. Checker fixes flow into the Player for free; a hard fork would rot.
  • Player-only additions: favorites, last-channel resume, keyboard zapping, autoplay on launch.
  • Prerequisites from this document: A's archive playback, B's EPG store, C's grid. D is Checker-only.

Open design work

  • Playlist onboarding and switching without the checker's Open/Save machinery.
  • Zapping model: number entry, channel history, previous-channel toggle, remote-friendly keyboard map.
  • Guide interactions on the watch screen vs the full Guide view; mini-guide overlay while watching.
  • VOD/series content types (parser already tags content_type); whether they get a separate browse surface.
  • Settings surface: which checker settings survive (proxy, external player, ffmpeg) and what player-specific ones are added (autoplay, startup channel, buffer size).
  • Packaging: product name, icon, AUR/release pipeline alongside the checker artifacts.
