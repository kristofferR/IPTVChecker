  • EPG infra (phase 2): XMLTV download + parse in Rust, streamed and gzip-aware (provider files reach hundreds of MB), disk-cached per source, indexed by tvg-id. Also upgrades the report panel's EPG coverage stat to real programme data.

Before verification it scores advertised coverage only; after, it blends coverage, reliability (verified vs broken), and real depth. Playlists with zero catch-up show N/A and the weights renormalize, so scores stay comparable.

  • Effort: medium; reuses the existing checker engine and latency plumbing.

Build order

PhaseShipsNotes
1 DetectionRust catch-up fields + Xtream archive fields, table column, pill, Status filter, selection countsAttrs already parsed, just unread. Releasable on its own.
2 PlaybackXMLTV EPG store, archive URL builder, player seek work, sidebar Archive card (programme list, picker fallback), spot probesLongest-lead phase; card ships once, in final form.
3 GuideTable/Guide switch, dense EPG grid, right-click entryBuilt as a shared component; doubles as the Player flavor's guide.
4 VerificationOpt-in scan phase, graduated chips, report section, fourth score componentChecker-only; nothing in the Player flavor depends on it.

Tracked in the checklist comment on issue #229. The IPTV Player flavor is a separate track (issue #231) with its own design document; phases 2-3 build its shared core (archive URL builder, XMLTV store, seek player, Guide grid) as checker-independent modules.
